# SpotifyScraper controlled discovery pilot — 2026-10-03

The owner superseded the older SpotifyScraper trial's ban on Spotify's internal endpoint and its release-date gate. A stable Spotify release ID absent from a complete successful baseline or earlier successful poll is the discovery signal. A release date helps review but is optional. This pilot uses pinned `spotifyscraper==3.9.2` for metadata only; it is never an audio source. It depends on Spotify's public web-player embed and `api-partner.spotify.com` Pathfinder responses and may break with upstream changes, region changes, 401/403/429 responses, or access controls. It is self-hosted, but not an independent Spotify fallback. SpotAPI remains unproven; wolfX gave unrelated Yas releases in the feasibility study and is excluded. SoundCloud is an independent source.

The adapter validates every Pathfinder discography page before the package can flatten it: expected offset, group count versus reported total, stable total across pages, nonempty release groups, distinct 22-character Spotify album IDs, title, response size, and a completed sequence. Missing discography data, a short page, a failed later page, or a non-200 response raises a source failure and cannot advance `last_success_at` or baseline completion. The request budget is 14 per call, page budget 10, response budget 2 MB, and HTTP timeout 8 seconds with no automatic retry. 429 `Retry-After` seconds are honored by source backoff. Each source has its own failure count and next-due time; failures do not stop later sources. First baseline persists historical IDs only. A later complete poll enriches at most 10 unseen IDs with album details and submits them to identity review, without assuming that regional catalog appearance means a new publication date. Spotify review approval links identity but creates no audio/publication queue item. Duplicate SoundCloud canonical titles are presented as review candidates.
